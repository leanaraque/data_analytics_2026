# 📦 Proyecto Final — Evaluación Integradora del Programa

> **Evaluación integradora final** del programa de Data Analytics. Pone a prueba tu capacidad de resolver un **caso de negocio real** aplicando todo lo aprendido: modelado de datos, consultas SQL, transformación y visualización con Power BI, y comunicación de hallazgos (**storytelling con datos**).

Has llegado al momento clave para **consolidar todo lo aprendido**. Esta evaluación no solo mide conocimientos, sino también tu habilidad para **resolver problemas prácticos y comunicar resultados** de manera efectiva. ¡Vamos a comenzar!

## ⭐ Importancia de la evaluación
Esta evaluación te permitirá:
- **Validar** tu comprensión integral del programa.
- **Identificar** áreas de fortaleza y oportunidades de mejora.
- **Prepararte** para aplicar estos conocimientos en entornos profesionales reales.

En el mundo empresarial y de marketing actual, la capacidad de analizar datos y comunicar *insights* es crucial para la toma de decisiones estratégicas. Esta evaluación simula situaciones reales donde deberás **interpretar datos, construir consultas SQL precisas, modelar datos y crear visualizaciones que cuenten una historia clara y convincente**.

## 💡 Consejos para el éxito
- **Leé cuidadosamente** cada pregunta y ejercicio.
- **Aplicá** los conceptos y buenas prácticas aprendidas.
- **Gestioná tu tiempo** para no quedarte sin completar alguna sección.
- **Reflexioná** sobre tus respuestas y **justificá** tus decisiones cuando se requiera.

> 📖 **Es de libro abierto:** podés usar tus apuntes y todos los recursos del programa (¡incluido este repositorio!) para apoyar tus respuestas. Se valorará la **precisión, la aplicación práctica y la claridad** en la comunicación.

---

## 📤 Formato y entrega — lo esencial
La entrega se realiza mediante un **único enlace de Google Docs** que funcione como un **reporte visual** del análisis, combinando explicaciones, gráficos, resultados y consultas SQL (con **capturas de pantalla** desde las herramientas).

> ⚠️ **Reglas de entrega (críticas):**
> - Solo se permite **un único enlace** de entrega.
> - El enlace debe permitir **visualización pública** o acceso para revisión.
> - **Todo** el contenido necesario debe estar **dentro** de la presentación.
> - **No** incluir enlaces externos para acceder a partes del análisis.
> - El evaluador debe comprender el análisis **únicamente** a partir de la presentación entregada.

👉 El paso a paso completo del formato y la **estructura recomendada de 7 secciones** están en la [**Guía de Presentación**](./guia-de-presentacion.md).

---

## ✅ Qué tenés que entregar (resumen)
Un **documento (Google Docs) de propuesta y desarrollo del proyecto** que, como mínimo, incluya:
1. El **problema de negocio** a resolver (la pregunta diagnóstica).
2. Las **fuentes de datos** identificadas.
3. Las **preguntas de investigación estadística**.
4. Un **boceto de los indicadores (KPIs)** a visualizar.

…y que se desarrolle siguiendo la **estructura recomendada de 7 secciones** (contexto → dataset → EDA → modelo y SQL → transformación → dashboard → conclusiones).

> 🧩 **Nota:** estos cuatro elementos son exactamente el **brief que empezaste en M1** (problema, fuentes, preguntas, KPIs). El proyecto final los toma como punto de partida y los lleva hasta el dashboard y las conclusiones. **El círculo se cierra.**
